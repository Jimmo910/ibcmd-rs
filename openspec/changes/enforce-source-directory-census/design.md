## Provenance and compatibility
SourceInventory keeps its public from_files constructor and files/file iteration unchanged. Introduce a private explicit DirectoryCensus::Unbound versus DirectoryCensus::Filesystem ledger. Only the private successful FS-capture path can create Filesystem, including a genuinely empty map. from_files is always Unbound, including from_files([]); unknown is never silently interpreted as proven empty. HeldSourceRoot baselines and final recaptures must both be Filesystem and compare their exact directory membership/type/identity. Missing provenance refuses custody revalidation.

Preserve SourceInventory's existing semantic PartialEq/Eq over its file map explicitly; adding private provenance must not accidentally change digest/classifier comparisons or turn semantic equality into authorization. digest_projection clears directory custody provenance as well as original-file capabilities. A cloned FS capture may retain its private proof, but file-only semantic projections cannot mint or promote it. Existing classification of changed files is unchanged; strict directory comparison belongs to held-source custody.

## Required anchored directory API
The separately owned API is RootAnchor::directory_witness(self: &Arc<Self>, relative: &str) -> Result<DirectoryWitness, SourceChangeError>. DirectoryWitness is opaque detached Clone/Debug/Eq identity with directory type implicit; it holds no File, Arc, mtime or per-member ancestor vector. The proposed constant-size witness includes root/directory identity plus a domain-separated SHA256 commitment of exact relative spelling, type and ordered ancestor identities; equality of the chain is cryptographic commitment equality, not a retained exact ancestor list or an ABA guarantee. Its exact donor contract still requires independent review. Caller retains the exact normalized spelling obtained from enumeration. The helper does not independently prove physical name spelling.

Unix must open each component with directory/NOFOLLOW checks from the SAME held root descriptor. Windows uses the reviewed #533 path opens with retained participating parent handles and actual-handle type/reparse/local NTFS/volume identity checks; this is not described as a native HANDLE-relative open. Transient descriptors drop on return, O(depth) at a time. Keep existing leaf access/share behavior unchanged. Cancellation and root/name binding are checked before/after traversal. No pathname metadata fallback or absolute reopen presented as equivalent to the Unix primitive. No ledger implementation may become production-ready before this dependency is reviewed.

WalkDir continues to enumerate candidate names, not confer custody. Each admitted directory name must acquire a helper witness; before/after witness/name validation and final anchored recapture must reject ordinary missing/type/reparse/identity changes. This remains a sequential census rather than a globally atomic enumeration or universal ABA defense. A directory replacement with a different identity at the same name is refused when witnessed; transient changes restored before observations are outside the claim.

## Common namespace and exact comparison
Validate normalized relative directory and file spellings in one case-folded namespace using the module's existing windows_path_key. Reject directory a versus file A as well as same-type aliases on case-sensitive filesystems. Keep original spelling in the ledger, so a case-only directory rename is changed even if folded keys match. Root identity remains bound separately by RootAnchor; the relative directory ledger excludes the root itself. Directory identity is compared without directory mtimes: creating or editing a child during separate operations must not falsely mean the retained directory itself was replaced.

## Retained metadata limits (proposal requiring compatibility review)
Caller-supplied Some(SourceTraversalLimits) keeps one cumulative entry/depth budget across files plus directories for each complete capture; no subtree reset, depth truncation or final-pass bypass. Every retained directory record charges exact UTF-8 spelling, folded key and fixed witness/bookkeeping storage with checked arithmetic BEFORE insertion. A finite cumulative metadata-byte limit is also required, not entry count alone. No stored ancestor chains or O(directory-count) open handles.

Proposed compatibility decision: retain existing None traversal/depth behavior for legacy callers, but add an explicit private retained-census ceiling of 500000 namespace entries and 64 MiB charged metadata on ALL FS captures. For Some limits the tighter entry bound applies, plus the same metadata ceiling. This is a new fail-closed admission at extreme legacy input sizes, not an unchanged-behavior claim; no new default depth64 is proposed. Exact byte-accounting constants, caller audit and boundary controls require reviewer/coordinator acceptance before production edits. The ceiling bounds newly retained proof, not a claim that existing legacy WalkDir allocation/work is globally bounded. Synthetic from_files inputs retain their existing file-only behavior.
