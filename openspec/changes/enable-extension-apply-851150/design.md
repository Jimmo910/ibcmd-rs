# Design

Reuse the existing source compiler, complete extension stage validator and transactional CAS publisher where native measurements prove the same invariant. Platform identity remains independent of XML dialect: exact RAS build plus measured database fingerprints are required. No blanket capability toggle precedes physical evidence.

Standard import --extension stages the selected image; apply --extension publishes that selected namespace, rather than applying ConfigSave. Both use the same owned library paths as direct commands. Unrelated namespace rows and the main configuration remain untouched. CLI dynamic/session choices must not silently promise an unmeasured online behavior.

Native measurements must classify all changed ConfigCAS/ConfigCASSave/registry/derived records; a final source equality alone cannot justify a missing storage side effect. Schema-changing extension edits must be modeled and measured or refused before writes. Existing 8.3.27 behavior is a regression control.

Tests use synthetic public Coverage objects and no application data. Private real-extension evidence stays outside the repository. Every changed extension version is incremented before building CFE and checked after publication.
